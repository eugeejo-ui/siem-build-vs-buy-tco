# L2 — 디스크 단가 비교표 · 세부계획

> 2026-09-16 작성 · **개정 4판 (3차 보정)** · 상태 **개정안 승인 대기** (수집 일부 진행 후 중단) · 승인 전 재개하지 않습니다
>
> **원 프로젝트 검증(`model_audit/`) 이후 재개합니다.** 이 계획서의 AWS 쪽 금액(508.1백만원, 460.7~559.9백만원 등)과 5년차 필요 용량(205.0TB 등)은 원 모델 산출값이며, 검증에서 S3 사본 ×2·1년차 보관량·연도별 누적·로컬 저장 계층 등이 판정되면 **바뀔 수 있습니다.** 배율(약 10~24배)도 함께 바뀝니다.

---

## 0. 한 줄 요약

**구하는 것:** SIEM 로그를 담을 디스크를 **AWS에서 빌릴 때**와 **서버에 꽂을 하드디스크를 사서 쓸 때**의 가격 비교표.

**구하지 않는 것**

- **오픈소스 직접 운영의 총비용이 아닙니다.** 소프트웨어·서버·인건비는 다루지 않습니다.
- **오픈소스 전용이 아닙니다.** Splunk를 사내 장비에 설치하는 경우(조합 4)도 포함합니다.
- **하나의 합계가 아닙니다.** 한 번 사는 값과 매달 내는 값을 합치지 않고 나란히 둡니다(CLAUDE.md §5.1).

> **개정 4판의 핵심 변경:** 사내 장비 쪽 기준을 **디스크어레이 → 서버 내장 하드디스크 드라이브**로 바꿨습니다(CLAUDE.md §5.5). 어레이 수집분은 참고값으로 보존합니다.

## 1. L2가 채우는 칸

결정 트리(CLAUDE.md §2.1)에서 **직접 구축** 아래 4개 조합 중, 원 프로젝트가 산출하지 않은 **사내 장비 열**의 **디스크**입니다.

| | 인프라: AWS 임대 | 인프라: 사내 장비 |
|---|---|---|
| SW: 오픈소스 | 조합 1 — 산출됨 | **조합 2 ← L2** |
| SW: Splunk | 조합 3 — 산출됨 | **조합 4 ← L2** |

서버는 이번 범위가 아닙니다. 관리형 위탁은 두 축에 속하지 않으므로 이 표에 없습니다.

## 2. 왜 서버 내장 드라이브인가

1. **카드뉴스는 직관적이고 간단해야 합니다.** "하드디스크 1TB에 얼마"는 누구나 이해합니다. 어레이는 케이스·제어 장치·RAID 설명이 따라붙습니다.
2. **원 모델의 AWS 계산과 조건이 같습니다.** 원 모델은 오픈소스 쪽을 *서버 + 서버마다 붙은 디스크(EBS) + 소프트웨어 복제본*으로 계산합니다. 사내에서 이에 대응하는 것은 **서버에 직접 꽂는 드라이브**입니다.
3. **"디스크만" 비교가 성립합니다.** AWS 디스크 값에는 서버가 없고 드라이브 값에도 서버가 없습니다. 반면 어레이 값에는 케이스와 제어 장치가 들어 있어 비교 조건이 어긋납니다.
4. **복제가 이중으로 들어가지 않습니다.** 오픈소스는 소프트웨어가 다른 서버에 복제본을 만듭니다. 어레이를 쓰면 장비의 RAID까지 겹쳐 용량을 이중으로 씁니다.
5. **가격 정보가 훨씬 풍부합니다.** 같은 6개월에 나라장터 드라이브 911건·354개 모델·용량 표기 100%(어레이는 362건·약 39%). 해외에도 TB당 가격을 매일 집계하는 사이트가 여럿 있습니다.

**원 모델 용량에 복제본이 이미 들어 있습니다.** 오픈소스 쪽 공식은 `일일량 × 보존일 × (1 + 복제본) × 1.15`이며 복제본 기본값은 1벌입니다. 따라서 **모델이 낸 용량만큼 드라이브를 사면 되고, RAID를 따로 고려하지 않습니다.** 용량 단위도 드라이브 표기와 같은 십진 TB(1TB = 1,000GB)입니다.

## 3. 조합마다 무게가 다릅니다

50GB/day · 5년 · 티어링 70% 기준, 원 모델 실측입니다(백만원).

| | 총 5년 | 인프라 | └ 디스크 | └ 서버 | **디스크 / 총** | 필요 용량 (1년차) |
|---|---|---|---|---|---|---|
| 조합 1 (오픈소스+AWS) | 1,148 | 774 | 500 | 274 | **43.5%** | 84.0TB |
| 조합 3 (Splunk+AWS) | 1,438 | 114 | 20 | 94 | **1.4%** | 7.0TB |

- **조합 4 (Splunk+사내 장비)** — 디스크가 총비용의 1.4%. **총액에는 거의 영향이 없습니다.** 이것도 결과로 표에 남깁니다(CLAUDE.md §4-4).

## 4. 산출물

### 4.1 비교표

| 로그량 (1년차) | 필요 용량 (5년차) | 사내 드라이브 — 제조사 상표 데이터센터용 · SATA | 사내 드라이브 — 제조사 상표 데이터센터용 · SAS | 사내 드라이브 — 서버 회사 상표 서버용 | AWS 5년 누적 |
|---|---|---|---|---|---|
| 20 / 50 / 100 GB/day | base (low~high) | 1회 구매액 · AWS 대비 배수 | 1회 구매액 · AWS 대비 배수 | 1회 구매액 · AWS 대비 배수 | base (low~high) |

사내 드라이브 칸은 **3개**입니다. 제조사 상표 쪽 SATA·SAS 중 하나를 고를 근거가 부족해 둘 다 싣습니다(정본 §3.14, CLAUDE.md §5.6).

조합 2와 조합 4를 **각각 한 장씩** 만듭니다. 필요 용량이 10배 이상 달라 한 표로 합치지 않습니다.

### 4.2 산정 규칙

1. **용량은 5년차 최대치.** 로그가 매년 늘어나므로 한 번 사서 5년 쓰려면 마지막 해 용량을 담아야 합니다. 복제본은 모델 공식에 이미 포함됩니다.
2. **AWS 5년은 연도별 증가 반영 누적.** 원 모델 `storage_cost()`를 연도마다 호출해 더합니다.
3. **드라이브 단가는 상표·용도·등급·연결방식을 맞춰 비교합니다.** 하드디스크 제조는 **사실상 Seagate·Western Digital·Toshiba 세 곳**(출하량 약 95%)이고, 그 외 상표는 이 세 곳의 제품에 자기 펌웨어·상표를 입힌 것입니다. ①**제조사 상표는 데이터센터용 등급만**(Exos·Ultrastar·Toshiba MG, 모델 번호로 판별) ②**서버 회사 상표는 서버용 부품만** — 디스크어레이·HCI 장비용 부품은 제외합니다(§5.5와 같은 이유) ③**연결방식(SATA·SAS)을 구분해 기록합니다** — 같은 제조사·같은 등급에서 SAS가 SATA보다 약 1.36배 비쌉니다 ④제조사 상표 쪽은 **SATA·SAS 두 값을 모두 본값으로 병기**합니다(CLAUDE.md §5.6). 각 구분의 **중앙값**을 본값으로 쓰고 최저·최고는 부록에 둡니다.
4. **드라이브 크기는 8TB 이상만** 씁니다. 대용량 로그 저장의 주력 크기이며, 이 범위에서는 크기보다 상표가 가격을 훨씬 크게 가릅니다.
5. **증가율은 원장 low/base/high(20/25/30%) 3값을 모두 씁니다.** 근거가 대리 지표이기 때문입니다.
6. **드라이브 개수를 정수로 올리지 않습니다.** 필요 용량 × TB당 단가로만 계산합니다. 과잉 정밀도 금지(CLAUDE.md §4-3).

> **개정 이력 — 폐기된 규칙:** 개정 3판의 "단가 구간은 행마다 계산된 용량으로 고른다(용량 구간 매칭)"는 **어레이의 총용량**에 적용되던 규칙이라 폐기했습니다. 드라이브는 한 장의 크기로 값이 매겨지고, 실측 결과 크기보다 **상표·용도·연결방식**이 가격을 가릅니다(서버용 부품끼리 약 1.7~2.3배, §4.3).

### 4.3 상표가 가격을 가르는 정도 (2026 상반기 참고 표본)

8TB 이상 드라이브의 TB당 단가입니다.

| 크기 | 제조사 상표 중앙 | 서버·스토리지 상표 중앙 |
|---|---|---|
| 8~12TB | 95,300원 | 449,700원 |
| 12~16TB | 118,333원 | 385,500원 |
| 16TB 이상 | 135,633원 | 366,212원 |
| 8TB 이상 전체 (등급 혼합) | 105,233원 (141개) | 397,062원 (112개) |
| 8TB 이상, 데이터센터용만 (1차 정정) | 115,800원 (73개) | 397,062원 (112개) |

**2차 정정 — 연결방식·장비 용도까지 맞춘 값**

| 구분 | 개수 | 중앙값 |
|---|---|---|
| 제조사 상표 · 데이터센터용 · SATA | 32 | **101,500원** |
| 제조사 상표 · 데이터센터용 · SAS | 36 | **137,638원** |
| 서버 회사 상표 · **서버용** (Dell 13 · Lenovo 1) | 14 | **237,979원** |
| 스토리지 회사 상표 · 디스크어레이·HCI용 (참고) | 92 | 427,400원 |

등급을 맞추지 않으면 3.77배, 등급만 맞추면 3.43배, 연결방식까지 맞추면 2.94배, **서버용 부품끼리 보면 약 1.7배(SAS)~2.3배(SATA)** 입니다. 1차 정정의 비교 상대 112개 중 92개가 디스크어레이 부품이었기 때문입니다. 검증 경위·출처·한계는 정본 §3.12, 재현은 `check_grade_interface.py`.

어느 쪽을 쓸지는 조직의 서버 구매 방식에 따라 다르므로 **두 값을 모두 제시**하고 하나를 고르지 않습니다. 제조사 상표 쪽도 같은 이유로 **SATA·SAS를 모두 제시**합니다(정본 §3.14).

**3차 보정 — 연결방식 배율은 용량마다 다릅니다** (같은 용량끼리 SAS/SATA 중앙값 비)

| 용량 | SATA 개수 | SAS 개수 | SAS / SATA |
|---|---|---|---|
| 8TB | 8 | 5 | 1.16배 |
| 10TB | 5 | 10 | 1.39배 |
| 12TB | 5 | 11 | 1.56배 |
| 14TB | 5 | 4 | **2.90배** |
| 16TB | 4 | 3 | 1.11배 |
| 18TB | 2 | 1 | 1.03배 |
| 20TB | 2 | 1 | 1.19배 |
| 24TB | 1 | 1 | 1.26배 |

전체 1.36배는 용량 구성이 섞인 중앙값 비교입니다. 대부분 **1.0~1.6배**이고 14TB만 튀며, 칸마다 1~11개라 얇습니다. 본 수집 후 같은 표를 다시 만들어 결과 문서에 싣습니다.

### 4.5 반드시 함께 적을 단서 5가지

1. **드라이브 표기 용량 기준.** 복제본 1벌은 모델 용량에 포함되어 있고, 서버에 꽂는 방식이라 RAID는 따로 고려하지 않습니다.
2. **드라이브값만.** 서버·케이스·전력·유지보수·인건비 **미포함**. 오픈소스 쪽은 어차피 서버를 사야 합니다(모델상 5년 274백만원, 별도).
3. **AWS 쪽도 디스크만.** 서버(EC2)는 양쪽 모두 제외입니다.
4. **디스크 등급 차이 — 사내 장비에 유리한 쪽으로 기울어 있습니다.** AWS 쪽은 최근 로그(용량의 약 30%)를 SSD에 두는데, 사내 쪽은 전량 하드디스크로 계산합니다.
5. **공공조달 가격, 조회 시점 기준.** 민간 협상가가 아니며, 조달청 API는 **현재 유효한 카탈로그**만 돌려줍니다(§6).

### 4.6 차트 1점

원 프로젝트 `src/make_charts.py`의 한글 폰트 선택 로직을 읽어서 같은 방식으로 구현합니다. 원 파일은 수정하지 않습니다.

### 4.7 참고값 — 디스크어레이

L2에서 이미 수집한 어레이 195건(중복 제거)은 **공유 저장소를 쓰는 조직을 위한 참고값**으로 결과 문서 부록에 둡니다. 본표에는 넣지 않습니다.

## 5. 작업 항목

모든 신규 파일은 `linkedin/L2_pricing_fetch/` 안에 둡니다. 원 모델은 import해서 호출만 합니다.

### 5.1 나라장터 — `g2b_collect.py`

- 품명 **`하드디스크드라이브`**를 본 수집 대상으로 전환
- 조회 기간은 등록일 **2025-10 이후**가 실제 데이터 구간입니다(§6). 기존 반기 4구간을 그대로 쓰되 빈 구간이 나와도 정상입니다.
- **상표 구분**(제조사 3사 / 그 외), **등급 판별**(모델 번호 명명 규칙), **연결방식 판별**(모델 번호·부품번호), **장비 용도 구분**(서버용 / 디스크어레이·HCI용), **8TB 이상** 필터를 집계에 추가. 판별 규칙은 `check_grade_interface.py`의 것을 옮겨 씁니다
- 서버용 표본이 14개로 얇으므로 전체 기간 수집 후 **서버용 부품번호의 연결방식·등급을 추가 확인**합니다(현재 Dell 11개 미확인)
- 제조사 표기 통일표 보강 — `Western digital`/`Western Digital`, 오타 `Segate`, `Toshiba`
- 어레이 수집분은 `out/g2b_*`에서 `out/array_ref_*`로 이름을 바꿔 참고값으로 보존

### 5.2 AWS — `aws_collect.py`

- io2의 단위 표기가 `GB-Mo`가 아니라 **`GB-month`**여서 누락됐습니다. 두 표기를 모두 받도록 고친 뒤 재실행
- 나머지(원장 대조, S3 사용량 구간 보존)는 기존대로

### 5.3 비교표 — `build_table.py`

- 필요 용량과 AWS 5년 누적은 원 모델 `compute_capacity()`, `storage_cost()`, `_volume_at_year()` 호출로 산출
- 증가율만 low/base/high로 바꾸고 단가는 base로 고정 — 원 모델 `compute_tco()`와 같은 방식
- 100GB/day 행은 5년차 로그량이 원 모델 분석 상한(200GB/day)을 넘으므로 **외삽 표시**

### 5.4 검증 — `verify_l2.py`

pytest가 자동 수집하지 않는 이름입니다(`pytest.ini`에 수집 경로 제한이 없어 `test_*.py`를 두면 원 프로젝트 `pytest` 결과가 바뀜).

- 사내 경로와 AWS 경로가 같은 값을 내면 실패
- 필요 용량이 `compute_capacity()` 재호출 값과 다르면 실패
- 상표 구분에서 분류되지 않은 드라이브가 있으면 실패
- 8TB 미만 드라이브가 본값 계산에 섞이면 실패
- 제조사 상표 본값에 데이터센터용이 아닌 등급이 섞이면 실패
- 서버 회사 상표 본값에 디스크어레이·HCI 장비 부품이 섞이면 실패
- 연결방식 판별 규칙의 확인 쌍(`HUH721212AL5204`=SAS/`…ALE600`=SATA, `ST20000NM002D`=SAS/`…NM007D`=SATA 등)이 기대값과 다르면 실패
- 제조사 상표 본값이 **SATA·SAS 둘 다** 산출되지 않으면 실패, 연결방식 미판별 드라이브가 본값에 섞이면 실패
- 용량별 SAS/SATA 배율표가 결과에 없으면 실패
- 등급 판별 규칙의 알려진 모델 번호(`ST…NM`, `ST…VX`, `HUH7…`, `WD…PURP` 등)가 기대 등급과 다르면 실패
- 증가율 3값 중 하나라도 빠지면 실패
- 상표 구분별 표본이 30건 미만이면 경고, 0건이면 실패
- 출력 파일에 인증키 흔적이 있으면 실패

## 6. 중단 시점까지의 진행 현황

| 항목 | 상태 |
|---|---|
| 품명 재탐색 (날짜 범위 포함) | 완료 |
| 디스크어레이 수집 668건 → 중복 제거 195건 | 완료 → **참고값으로 전환** |
| 하드디스크드라이브 참고 표본 911건 → 354개 모델 | 완료 (2026 상반기만) |
| AWS 원장 대조 | 5건 중 4건 일치, io2 단위 표기 문제로 1건 미확인 |

**진행 중 발견한 사실 3가지**

1. **날짜 조건은 등록일 기준입니다**(수집 668건 전부 구간 안).
2. **조달청 API는 현재 유효한 카탈로그만 돌려줍니다.** 가장 오래된 등록일이 2025-10-20이고 계약 종료일은 전부 2026-10 이후입니다. 2025년 1~9월은 비어 있습니다. 기간을 넓혀 표본을 늘리려던 의도는 효과가 없었고, 대신 **가장 최신 가격**이라는 뜻입니다.
3. **L1의 "저장장치 0건" 판정은 틀렸습니다.** L1은 날짜 없이 조회해 과소 집계됐고, 날짜를 넣으면 169건입니다. 다만 대부분 배터리 설비(BESS)이고 스토리지 관련은 `SSD저장장치` 8건(SSD 단품)뿐입니다. `스토리지`·`NAS`·`테이프`·`백업`은 날짜를 넣어도 0건입니다.

## 7. 다음 단계에 미치는 영향

**L4 충돌은 그대로입니다.** 한 번 사는 값과 매달 내는 값을 합치지 않기로 했으므로(CLAUDE.md §5.1), 조합 2·4는 5년 총비용도 손익분기도 만들 수 없습니다. (가) 현 결정 유지 / (나) §5.1 재검토 중 결정이 필요합니다. L2 실행에는 영향이 없습니다.

**L5 훅이 하나 생겼습니다.** *서버에 꽂는 같은 하드디스크라도 서버 회사 상표가 붙으면 약 2배.* (서버용 표본 14개 — L2 확정 전 사용 보류)

**L5 카드가 한 장 늘 수 있습니다.** 제조사 상표 쪽을 SATA·SAS로 나눠 싣기로 해, 두 방식의 차이(PC 출신 대 서버 출신)를 설명하는 카드가 필요할 수 있습니다(정본 §3.14).

## 8. 이 단계에서 하지 않는 것

- **원 프로젝트 수정 일체** — `src/`·`data/`·`docs/`·`tests/`·`README*`. 새 파일 생성도 포함
- 조합 2·4의 5년 총비용·손익분기 산출
- 서버·케이스·섀시 가격, 네트워크 장비
- 인건비 (L4 소관)
- 한 번 사는 값의 연 단위 분할, 유지보수·전력·랙 추정
- **최근 로그용 SSD를 따로 산정하는 일** — 단서 ④로 편향 방향만 공개합니다
- 드라이브 개수의 정수 올림
- 해외 가격 추적 사이트 수집 — 미국 소비자가(달러)라 국내 기업 구매가와 달라 본표에 쓰지 않습니다
- S3 사용량 구간 단가를 원 모델에 반영하는 일 (원 프로젝트 검증으로 이관, §9)

## 9. 보류 중인 별건

원장 `object_price`가 0.025 단일값이나 AWS S3는 구간별 체감(50TB↑ $0.024, 500TB↑ $0.023)입니다. 원 프로젝트 수정이므로 **원 프로젝트 검증(`model_audit/`) 항목 D9로 이관**했습니다. 승인·수정 여부는 그쪽 관문에서 정하며, L2는 그 결과를 따릅니다.

## 10. 완료 기준

1. 조합 2·4 각각, 20·50·100GB/day × 증가율 3값에 대해 **사내 드라이브 3구분(제조사·SATA / 제조사·SAS / 서버 회사 상표) + AWS 5년 누적**을 모두 채움
2. 필요 용량이 **5년차 최대치**이며 `compute_capacity()` 호출로 산출됨
3. 드라이브 단가가 **상표·용도·등급·연결방식·8TB 이상** 규칙으로 산출되고, 구분별 개수와 판별 근거 수준(확인·추정·미확인)이 명시됨
4. 단서 5가지가 표에 함께 적힘
5. 상표 구분별 표본 수, 파싱 제외 건수가 명시됨
6. 100GB/day 행에 외삽 표시
7. 디스크어레이 참고값이 부록에 있음
8. `verify_l2.py` 통과, 원 프로젝트 `pytest` 결과 변화 없음
9. `git status -- docs/ src/ data/ tests/ README.md README.ko.md` 결과가 비어 있음
10. `L2_result.md` 작성

## 11. 개정 이력

| 판 | 변경 |
|---|---|
| 4판 3차 보정 | 제조사 상표 본값을 **SATA·SAS 병기**로 확정(정본 §3.14). 비교표 사내 드라이브 칸 2 → 3. 용량별 SAS/SATA 배율표(1.03~2.90배) 추가. 검증 항목 2개·완료 기준 1 갱신. L5 카드 1장 추가 가능성 기록 |
| 4판 2차 보정 | "기업용 부품=데이터센터급" 가정을 부품번호로 검증. 연결방식 효과 1.36배. 비교 상대 112개 중 92개가 디스크어레이 부품 → 서버용 14개로 교체. 배율 약 3.4배 → 약 1.7~2.3배, 예시 약 6~21배 → 약 10~24배. 제조사 쪽 연결방식 미결 |
| 4판 보정 | 제조사 상표 본값을 **데이터센터용 등급으로 한정**(105,233 → 115,800원/TB). 배율 3.77 → 3.43배, 예시 약 24배 → 약 21배. "세 곳뿐" → "사실상 세 곳(출하량 약 95%)" |
| 4판 | 사내 장비 기준을 **서버 내장 드라이브**로 교체. 용량 구간 매칭 규칙 폐기 → **상표 구분** 규칙. 단서 ①④⑤ 재작성. 진행 현황·발견 사실 기록 |
| 3판 | 증가율 3값 병기, 단가 구간을 행마다 선택(20GB/day는 50~100TB) |
| 2판 | 명칭을 디스크 단가 비교표로 좁힘. 조합별 무게, 5년차 최대 용량, 증가 반영 누적. 파일 위치를 `src/` → `linkedin/`으로 정정. "10~27배" → "약 4~18배" 정정 |
| 초판 | 스토리지 단가 비교표 |

**초판~3판의 정정 내역 요약**

- 초판은 AWS 5년을 1년차×5로 계산해 **로그 증가를 빠뜨렸고**, 사내 장비를 1년차 용량으로 잡았습니다("84TB, 310백만 대 11.5~33.6백만, 10~27배").
- 초판은 수집기를 `src/pricing_fetch/`에 두려 했으나 `src/`는 원 프로젝트 읽기 전용 영역입니다.
- 2판은 "조합 2는 100TB 이상 구간"으로 일괄 적용했으나 20GB/day 행은 50~100TB였습니다.
- 초판~3판의 "약 4~18배(중앙 약 9배)"는 **어레이 단가** 기준이었습니다. 드라이브 기준 참고 표본으로는 **약 10~24배**입니다(4판 초안 "약 6~24배"는 등급 혼합, 1차 보정 "약 6~21배"는 비교 상대가 디스크어레이 부품 위주였던 값).
