## 2. 인증 경위 — 해결됨

### 최초 진단은 무효였습니다

L1-b 착수 시 403 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`(코드 30)가 발생했습니다. 이때 "Encoding 키 원문 vs Decoding 키 + params" 비교로 인코딩 문제를 배제했다고 기록했으나, **두 방식은 최종 전송 바이트가 동일**합니다. 비교가 성립하지 않는 시험으로 원인을 배제했습니다.

### 재검증

| 시험 | 범위 | 결과 |
|---|---|---|
| 전송 형태 매트릭스 | {Encoding 원문, Decoding 비인코딩, 이중 인코딩, serviceKey 단독, `_type`} × {https, http} = 10건 | 전부 403/코드30 |
| **서비스 매트릭스** | 조달청 4개 서비스 동일 키 | **입찰공고만 200** |

**판별 원리:** 코드 30이 아닌 응답이면 그 API는 인증을 통과한 것입니다.

동일한 키로 입찰공고(15129394)가 `resultCode=00`을 반환했습니다. 즉 **키는 유효하며 이미 사용 중**이었고, 실패 원인은 data.go.kr이 **키는 계정 단위로 발급하되 접근 권한은 API 단위로 부여**하는 구조였습니다.

### 해결

사용자가 [15129471 종합쇼핑몰 품목정보](https://www.data.go.kr/data/15129471/openapi.do)를 활용신청한 직후 동일 키로 `resultCode=00 / totalCount=23,074` 확인. **키 변경 없이 해소되었습니다.**

| API | 현재 상태 |
|---|---|
| 15129471 종합쇼핑몰 품목정보 | **접근 가능** |
| 15129394 입찰공고 | 접근 가능 |
| 15129397 낙찰정보 | 미신청 (L2 보완 출처) |
| 15129427 계약정보 | 미신청 (L2 보완 출처) |

### 경로 오기 정정

`L1_schema_survey.md` §7에서 계약정보 경로를 `/ad/`로 추측했으나 실제는 **`/ao/CntrctInfoService`** 입니다. 서비스별 확정 경로는 `service_matrix.py`에 있습니다.

## 3. 실측 결과

**대상:** 품명 `디스크어레이`, 등록일 2026-01-01 ~ 06-30, **전수 362건**


### ① 분류 — 통과

`prdctClsfcNoNm` 필터는 **부분일치**입니다(`디스크어레이` → `하드디스크어레이` 적중). 공식 품명은 `하드디스크어레이`이며, `스토리지`·`저장장치`·`네트워크저장장치`는 **0건**입니다. 키워드 선택이 결과를 좌우합니다.

> **후속 정정 (L2, 2026-09-16) — 위 "0건" 판정은 틀렸습니다.** 이 탐색은 **날짜 범위 없이** 조회했고, 같은 조건에서 `디스크어레이`도 2건만 나왔습니다(날짜를 넣으면 362건). 날짜 범위를 넣어 다시 조회하자 `저장장치`는 **169건**이었습니다. 다만 대부분 배터리 설비(BESS)이고 스토리지 관련은 `SSD저장장치` 8건뿐입니다. `스토리지`는 날짜를 넣어도 0건입니다. 또한 `하드디스크드라이브`(개별 드라이브)가 6개월 911건으로 대량 존재하며, L2는 이것을 본값 출처로 전환했습니다. 본문은 당시 기록으로 남겨 둡니다. 상세는 `L2_pricing_fetch/L2_plan.md` §6.

## 4. 가장 중요한 발견 — 용량 구간에 따라 단가가 급락합니다

100TB 이상 대용량 SKU만 추리면 단가가 전혀 다릅니다.

| 원/TB | 용량 | 총액 | 제조사 |
|---|---|---|---|
| 14,409 | 1,640TB | 23,630,000 | Dell PowerVault ME5084 |
| 135,000 | 400TB | 54,000,000 | 한결피아이에프 |
| 137,278 | 288TB | 39,536,000 | 이담에스티 |
| 148,889 | 198TB | 29,480,000 | 투비 |
| 152,639 | 144TB | 21,980,000 | Dell |

**중앙값 976,250원/TB 대비 6~7배 저렴**합니다.

**본 프로젝트에 직결됩니다.** SIEM 로그 저장은 2년 보관 전제라 100TB를 넘는 대용량 구간입니다. **중앙값을 쓰면 온프렘 비용을 크게 과대 산정**하게 됩니다.

### 참고 — AWS 5년 환산과의 격차

| 방식 | 5년 원/TB |
|---|---|
| AWS EBS gp3 | 약 7,497,000 |
| AWS S3 Standard | 약 2,055,000 |
| 온프렘 대용량 어레이 (CapEx 1회) | 약 137,000 ~ 152,000 |

**이 수치를 그대로 쓰면 안 됩니다.** 두 가지 이유입니다.

1. **계층이 다릅니다.** 대용량 HDD 어레이는 S3/cold 계층에 대응하며, SSD 기반 EBS gp3와 동급이 아닙니다. 계층을 맞춰 비교해야 합니다.
2. **온프렘에는 미포함 비용이 있습니다.** 유지보수료(통상 리스트가의 연 15~20%), 랙·전력·냉각, 운영 인건비, 감가 기간. 이것이 L3의 과제입니다.

**검증 필요:** Dell PowerVault ME5084 1.64PB가 23,630,000원(14,409원/TB)인 건은 **디스크 미포함 섀시일 가능성**이 있습니다. 규격서 첨부(`specDocAtchFileNmUrl1~5`)로 확인해야 하며, 확인 전까지 이 값은 사용하지 않습니다. 방어 가능한 값은 **100TB 이상 구간의 135,000~152,639원/TB**입니다.

## 5. L2로 넘기는 설계 쟁점

1. **본체/디스크 SKU 결합.** 62%가 용량 없는 본체 SKU입니다. 완제품 단가를 얻으려면 결합 규칙이 필요하거나, 용량 기재 SKU만 사용해야 합니다.
2. **용량 구간별 단가 체계.** 단일값 금지. 용량 구간을 축으로 하는 스키마가 필요합니다 — AWS S3 볼륨 계층 할인(§L1_result 이전판 §4)과 같은 구조입니다.
3. **제조사 정규화 테이블.** 표기 변형 매핑.
4. **파싱 실패 처리.** 37.8%만 쓰므로 `status`/`confidence`에 표본 한계를 명시해야 합니다.
5. **응답 구조 분기.** 종합쇼핑몰은 `body.items.item` 중첩, 입찰공고는 `body.items` 배열 직접입니다.
6. **타임아웃.** 날짜 범위가 넓으면 응답이 느립니다. 재시도와 90초 이상 타임아웃이 필요합니다.
7. **AWS 트랙.** Bulk API는 인증 불필요(S3 서울 513KB). EC2/EBS는 **296MB**라 스트리밍 필터 필요. S3 볼륨 계층 할인(50TB↑ $0.024, 500TB↑ $0.023)이 `pricing.yaml`에 누락돼 있습니다.
